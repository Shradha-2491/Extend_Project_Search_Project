What this means
----------------
This is TokenStore.kt's EncryptedSharedPreferences (AndroidX Security
Crypto), configured with AES256_SIV for key encryption and AES256_GCM for
value encryption, with the master key held in the Android Keystore
(hardware-backed on real devices) -- never written to disk itself.

Two things confirm this is genuinely encrypted, not just base64-encoded
plaintext:
  1. Even the entry NAMES are ciphertext (e.g. "AWgNlnVewyBc72MB...") --
     a plain SharedPreferences file would show readable keys like
     "access_token" or "refresh_token". AES256_SIV deterministically
     encrypts keys so the same logical key always maps to the same
     ciphertext (needed so the app can still look values up by name),
     without ever storing the plaintext key name.
  2. The values are opaque AES-GCM ciphertext blocks -- no substring of
     this file contains a readable JWT (no "eyJ..." header, which is what
     a plaintext-stored access/refresh token would look like), a username,
     or a role string.
  3. No databases/ directory exists at all -- tokens are not additionally
     cached in a SQLite database somewhere else in the app's private
     storage.

Combined with allowBackup="false" (see apk_debuggable_check.txt), this
closes both halves of the local-storage risk: the data is encrypted at
rest, AND the OS-level export path that could otherwise exfiltrate this
file (adb backup / auto-backup to Google) is disabled entirely.
